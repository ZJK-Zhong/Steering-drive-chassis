# 换电脑后必须检查的环境配置

适用于从 GitHub 克隆 Steering-drive-chassis 后，在另一台 Windows 电脑上配置编译、下载和调试环境。以下文件路径均相对于仓库根目录。

先在 VS Code 中直接打开仓库根目录，再按本机安装位置修改下列配置。

## 1. 安装工具，先让命令行能编译

默认目标为 RoboMaster C 型板的 STM32F407IG，使用 ARM GCC、硬浮点 Cortex-M4 配置。已有 Make 构建曾使用 ARM GCC 13.3.0 验证。

| 工具 | 用途 | 何时需要 |
| --- | --- | --- |
| ARM GNU Toolchain（含 `arm-none-eabi-gcc/objcopy/size` 和 newlib） | 交叉编译、链接、生成固件 | 必需 |
| MSYS2 MinGW64 的 `mingw32-make` | 执行默认 Makefile | 使用默认 Windows 构建时必需 |
| MSYS2 的 `bash.exe`、`cygpath` | 运行现有 VS Code 任务 | 使用 `.vscode/tasks.json` 时必需 |
| OpenOCD | CMSIS-DAP 下载、Cortex-Debug 的 DAP 调试 | 使用对应方式时需要 |
| SEGGER J-Link 软件 | J-Link 调试与现有 JFlash 下载目标 | 使用对应方式时需要 |
| VS Code C/C++、Cortex-Debug、Orbit 扩展 | 补全、对应调试入口 | 按所选方式安装；命令行编译不依赖这些扩展 |
| Python 与 `tests/requirements.txt` 中依赖 | 软件回归测试 | 运行测试时需要，编译正常固件不需要 |

原作者使用 `D:/msys64`；你的安装位置可以不同。以下示例假设安装在 `C:/msys64`，请替换为真实路径。

在工程根目录的 PowerShell 终端执行：

```powershell
$env:PATH = 'C:\msys64\mingw64\bin;' + $env:PATH
arm-none-eabi-gcc --version
mingw32-make --version
mingw32-make -j8
```

这是当前终端的临时 PATH。修改系统 PATH 后，需重新打开 VS Code/终端。只有安装扩展，没有安装可执行工具，仍不能编译。

Makefile 也接受 `GCC_PATH` 参数，例如 `mingw32-make -j8 GCC_PATH=C:/ArmToolchain/bin`；该变量只指定 ARM 编译工具目录，不会替你安装 Make、OpenOCD 等工具。现有工具命令没有完整处理带空格的工具链路径，优先选不含空格的安装位置。

## 2. 修改 `.vscode/settings.json`

本工程需要检查以下配置项：

| 配置项 | 当前配置 | 应改成什么 |
| --- | --- | --- |
| `makefile.makePath` | `D:/msys64/mingw64/bin/mingw32-make.exe` | 本机 Make 的完整路径 |
| `cortex-debug.armToolchainPath` | `D:/msys64/mingw64/bin` | 本机 ARM 工具链的 `bin` 目录 |
| `cortex-debug.gdbPath` | `D:/msys64/mingw64/bin/gdb-multiarch.exe` | 本机可调试 ARM 的 GDB 路径，如工具链中的 `arm-none-eabi-gdb.exe` |
| `cortex-debug.openocdPath` | `D:/msys64/mingw64/bin/openocd.exe` | 本机 OpenOCD 路径；用于 Cortex-Debug 的 OpenOCD 配置 |
| `cortex-debug.JLinkGDBServerPath` | `C:/Program Files/SEGGER/JLink/JLinkGDBServerCL.exe` | 本机 J-Link GDB Server 路径；仅 J-Link 调试需要 |
| `orbit.defaultProgram` | 作者电脑 `E:/RM/new steering sentry/.../build/...elf` 的绝对路径 | 本机当前工程编译得到的 ELF 的真实路径 |

`orbit.defaultProgram` 不要保留作者的 E 盘路径。可用正斜杠书写 Windows JSON 路径；用反斜杠时要写成 `\\`。

例如，若本工程克隆到 `C:/RM/Steering-drive-chassis`：

```json
"orbit.defaultProgram": "C:/RM/Steering-drive-chassis/build/Steering-drive-chassis.elf"
```

`.vscode/launch.json` 的 `program` / `executable` 已使用 `${workspaceFolder}` 或 `${workspaceRoot}`，正常迁移无需替换成本机绝对路径。建议在 VS Code 中直接打开所选仓库根目录，确保该变量指向有 Makefile 的目录。

## 3. 修改 `.vscode/tasks.json`

`build task`、`download dap`、`download jlink` 三个任务的 `options.shell.executable` 都写死了：

```json
"executable": "D:\\msys64\\usr\\bin\\bash.exe"
```

将三处改为本机路径，如 `C:/msys64/usr/bin/bash.exe`。

任务中的 `export PATH=/mingw64/bin:$PATH` 和 `cygpath` 属于 MSYS2 用法。继续使用 MinGW64 环境时保留；若改用其他环境，需要一起调整命令和 PATH。只改终端默认 Shell 不会覆盖任务里指定的 Shell。`-j24` 是并行数，可按电脑情况调低。

## 4. 修改 `.vscode/c_cpp_properties.json`

将 `compilerPath` 的 `D:/msys64/mingw64/bin/arm-none-eabi-gcc.exe` 改为本机 ARM GCC 路径。

此项主要影响补全、头文件解析和代码红线。真正编译时用的是 Makefile/PATH，因此可能出现“代码标红但能编译”或“补全正常但不能编译”，应分别检查。

## 5. J-Link 下载的路径需要单独处理

`Makefile` 默认：

```makefile
SEGGER_DIR ?= C:/Program Files/SEGGER/JLink
JFLASH ?= $(SEGGER_DIR)/JFlash.exe
```

安装位置不同，可修改 `SEGGER_DIR`，也可下载时覆盖：

```powershell
mingw32-make download_jlink SEGGER_DIR="C:/Tools/SEGGER/JLink"
```

`download_jlink` 当前调用 **JFlash.exe**，`JLinkGDBServerPath` 则用于 Cortex-Debug；这是两个配置入口。使用 CMSIS-DAP 时执行 `mingw32-make download_dap`，并确保终端 PATH 中能找到 `openocd`。只设置 `cortex-debug.openocdPath` 不会改变 Makefile 的 OpenOCD 搜索路径。
